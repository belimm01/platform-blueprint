# Platform Blueprint

[![CI](https://github.com/belimm01/platform-blueprint/actions/workflows/ci.yml/badge.svg)](https://github.com/belimm01/platform-blueprint/actions/workflows/ci.yml)

A reproducible reference implementation of an **Internal Developer Platform paved road**. Application teams describe a service through a small platform API; the tooling validates the contract and produces reviewable GitOps configuration with namespace isolation, resource policy, and an Argo CD deployment boundary.

This repository demonstrates the platform-engineering side of my work: Go automation, Kubernetes APIs, Crossplane contracts, GitOps, policy as code, and production-operability decisions. It is original public reference code and contains no employer source or configuration.

## What it demonstrates

- A stable, team-facing `ServiceClaim` contract instead of copied infrastructure YAML.
- A dependency-light Go CLI with deterministic rendering and race-tested unit coverage.
- Namespace, quota, and default network-policy guardrails generated by default.
- Argo CD as the only workload mutation path; application CI holds no cluster credential.
- A Crossplane v2 XRD as the infrastructure API boundary.
- Kyverno policy for workload probes and resource guarantees.
- ADR, security model, architecture, and operational runbook—not only manifests.

## Flow

```text
service claim --> platformctl validate/render --> reviewed Git change
                                                    |
                         +--------------------------+------------------+
                         |                                             |
                     Argo CD                                     Crossplane
                         |                                             |
                  workload + policy                         infrastructure claims
                         |                                             |
                         +---------------- Kubernetes / cloud ----------+
```

## Try it

Requires Go 1.23+; no cluster or cloud account is needed for validation and rendering.

```bash
make verify
go run ./cmd/platformctl validate -file examples/catalog-service.json
go run ./cmd/platformctl render -file examples/catalog-service.json > /tmp/catalog.yaml
```

The example renders a namespace boundary, quota, default-deny ingress policy, and Argo CD `Application`. `make verify` runs formatting, static analysis, race-tested unit coverage, contract validation, and strict Kubernetes schema validation for the generated built-in resources. Custom resources without a bundled schema are reported as skipped. Invalid input fails before any external mutation.

## Scope

The CLI and generated manifests are executable and covered by CI. The Crossplane and Kyverno resources are reference integration points: installing their controllers and connecting a real cloud account is deliberately outside the automated quickstart, because it requires operator-owned credentials and policy decisions.
